# Домашнє завдання — Воркшоп 8

**Тема:** Робота з фронтендом та бекендом — наскрізна фіча з AI
**Формат:** artifacts-first — ви робите одну фічу через усі чотири шари й
перевіряєте те, чого не перевіряють зелені тести
**Час:** ~2–2.5 години
**Здача:** Pull Request у starter-repo (CodeRabbit зробить авто-рев'ю)

---

## 0. Налаштування

```bash
gh repo fork koldovsky/2026-udc-08-frontend-backend-hw --clone
cd 2026-udc-08-frontend-backend-hw
git checkout -b ws08/<github-username>

cd app && npm install && npm test
npm run dev          # → http://localhost:3080
```

`npm test` — **9 зелених тестів**. `npm run dev` підіймає застосунок: у списку
зверху можна перемикатися між користувачами (Оля / Тарас).

Потрібно: Node 22+, GitHub account, Agentic IDE. **API-ключі не потрібні** —
жодних зовнішніх сервісів.

> Стек навмисно найпростіший: **Express + SQLite + звичайний HTML/JS, без
> збірки й без фреймворку**. Цей воркшоп — не про React, а про **шви між
> шарами**: UI → API → база → авторизація. Не додавайте бандлер.

### Що засіяно в репо

| Шлях | Що це |
|---|---|
| `app/src/db.js` | Схема + сідові дані: користувачі **Оля (id 1)** і **Тарас (id 2)**, три нотатки |
| `app/src/app.js` | Express-застосунок. Псевдосесія: клієнт передає заголовок **`x-user-id`** |
| `app/public/` | Мінімальний UI без збірки |
| `app/test/api.test.js` | 9 тестів на наявну поведінку — усі зелені |

> **Про автентифікацію.** Справжня сесія (cookie, JWT) навмисно поза скоупом:
> клієнт просто каже, хто він, заголовком `x-user-id`. Цей воркшоп про те, що
> відбувається **після** того, як ви вже знаєте, хто дзвонить.

### Фіча, яку ви робите: **архівування нотатки**

Наскрізно: кнопка в UI → ендпоінт → колонка в базі → перевірка прав.

---

## Task A — UI _(~30 хв)_

**Мета:** зробити частину інтерфейсу і **переконатись у браузері**, що вона
працює, а не повірити агенту на слово.

1. Додайте до кожної нотатки контрол «архівувати / повернути з архіву».
2. Дайте спосіб побачити архівовані (окремий фільтр, вкладка — на ваш смак) і
   притомний порожній стан.
3. **Перевірте в браузері**: дійдіть до потрібного стану, подивіться DOM або
   дерево доступності — не лише скріншот.
4. Доступність — не «потім»: справжня `<button>` з текстом або `aria-label`,
   розмір цілі, контраст. Найчастіші дефекти саме тут (див. слайди).

**Перевірка:** контрол видно, він працює, стан архіву видно в інтерфейсі; ви
особисто відкривали сторінку, а не покладались на «готово».

---

## Task B — API і база _(~30 хв)_

**Мета:** серверна частина тієї самої фічі.

1. Додайте колонку для ознаки архіву (міграція або зміна схеми в `db.js` —
   опишіть, що саме зробили).
2. Зробіть ендпоінт, що перемикає стан.
3. **Валідуйте на сервері.** Те, що UI не дає надіслати дурню, не рахується:
   клієнт контролюється користувачем.
4. Не віддавайте у відповіді зайвого — жодних внутрішніх полів «про всяк
   випадок».
5. Наявні 9 тестів мають лишитись зеленими; додайте свої.

**Перевірка:** `cd app && npm test` зелений; ендпоінт відповідає розумно на
некоректний вхід; у відповіді немає полів, яких клієнту знати не треба.

---

## Task C — авторизація _(~30 хв)_

**Мета:** найважливіше завдання воркшопу. Дві частини.

### C1. Ваш новий ендпоінт

Переконайтесь, що він працює **з власником**, а не просто «з id». Питання, на
яке має відповідати код: не «чи існує ця нотатка», а «**чи можна саме цьому
користувачеві саме цю нотатку**».

### C2. У засіяному репо є один зламаний ендпоінт

Він там **навмисно**, і ми показали його на воркшопі. Тож завдання — не
«здогадайся», а **відтворити витік власними руками** й полагодити: побачити на
слайді і зловити самому — різні речі.

- **Відтворіть.** Зайдіть як один користувач і дістаньте нотатку іншого.
  Зафіксуйте, що саме повернулось.
- **Полагодьте** — умовою по власнику **в самому запиті**, а не перевіркою
  після того, як рядок уже дістали.
- **Закрийте тестом, який ставить питання авторизації**: один користувач не
  має **прочитати** чуже. Тест має **червоніти на коді до вашої правки** —
  інакше ви не знаєте, чи він щось перевіряє.
  > У наборі вже є `will not delete someone else's note` — крос-юзерний тест,
  > але **на видалення**. Він зелений і до фіксу, тож він не рахується: візьміть
  > його як зразок і напишіть такий самий для читання.
- Усі **9 засіяних тестів зелені** — і залишаться зеленими, поки діра відкрита.
  Набір просто ніколи не ставить це питання. Ваш власний ендпоінт із Task B він
  так само не перевірить.

**Перевірка:** обидва ендпоінти (ваш і полагоджений) перевіряють власника; є
тест, що падав би до фіксу.

> 💡 Пройдіться **кожним** маршрутом, включно зі своїм, і спитайте: «звідки
> береться межа даних, які він поверне?» Якщо відповідь — «з `id` у запиті» і
> більше нізвідки, ви знайшли проблему. Псевдосесія через `x-user-id` робить
> перевірку тривіальною: той самий запит із чужим заголовком має отримати
> відмову, а не дані.

## Task D — що AI зробив не так _(~20 хв)_

**Мета:** зафіксувати реальні помилки, а не враження.

Заповніть `docs/ai-mistakes.md`. На кожен випадок:

- **Що просили** (промпт або задача)
- **Що видав** (конкретно — файл, рядок, поведінка)
- **Як помітили** (тест? браузер? рев'ю? випадково?)
- **Як полагодили**

Чесно в обидва боки: якщо агент зробив добре там, де ви чекали проблем, — це
теж результат, запишіть.

**Перевірка:** є щонайменше 3 записи з доказами.

> ⚠️ «Нічого не помітив» — валідний результат **лише якщо ви пишете, що саме
> перевіряли**. Список перевірок, які всі пройшли, — це результат. Порожній
> документ — ні.

- **Шлях 3 — набір тестів на авторизацію:** пройдіться кожним ендпоінтом «не
  тим користувачем» і зафіксуйте результат.

Необовʼязкове; відсутність — не помилка.

## Definition of Done

- [ ] **Task A:** UI архівування; перевірено в браузері; доступний контрол
- [ ] **Task B:** колонка + ендпоінт + **серверна** валідація; зайвих полів у відповіді немає
- [ ] **Task C:** ваш ендпоінт перевіряє власника; **засіяну діру знайдено й полагоджено разом із тестом**
- [ ] **Task D:** `docs/ai-mistakes.md` — ≥3 записи з доказами
- [ ] **Task E (bonus):** `docs/task-e-bonus.md` (опціонально)
- [ ] `cd app && npm test` зелений, включно з новими тестами на авторизацію
- [ ] Жодних секретів; `.env` не закомічено
